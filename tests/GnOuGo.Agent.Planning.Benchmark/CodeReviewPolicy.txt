Benchmark execution policy:
For this isolated benchmark only, use git_compare_refs followed by copilot_review as the review implementation. Other review implementations are outside this benchmark's execution authority. This constraint does not restrict the production catalog or the original saved session.
That implementation restriction applies only to code-review analysis. Dependency installation, manifest discovery, linters and tests may use any eligible execution capability, including an interactive execution agent, provided it works in the same owned clone and reports actual command results.
Generate one reusable workflow accepting a single PR URL and review instructions. The two supplied PR URLs are separate input cases, never two PRs in one execution.
Create exactly one isolated clone per execution. Install the project's declared dependencies before running available linters, unit tests and integration tests, using only that clone. Account for each review instruction in the returned evidence. Report checks that are absent or cannot run; never treat an unexecuted required check as passing.
Project technology and applicable check commands are runtime facts discovered from the cloned project's manifests. Inspect them before selecting commands; do not assume a framework or toolchain while planning. Review the actual pull request head revision against its base, including pull requests from a fork.
Manifest filenames do not establish manifest contents or commands: read the actual contents before selecting commands. A selected command implementation must document how its declared arguments or configuration target the owned clone and discovered project. A command configured to run in an unrelated fixed workspace cannot satisfy this requirement merely because its name describes a required check; do not assume an undeclared working-directory override or shell interpolation.
Generate an explanatory review. Its business decision is APPROVE only when every required check passes, otherwise REQUEST_CHANGES. Require explicit human permission before publishing that decision and its explanation. Rejected permission must perform no external publication.
Always delete only the clone and temporary directory owned by this execution in a finalizer, on success, failure and cancellation. Preserve the original execution error when cleanup also fails. A no-op finalizer does not satisfy cleanup.
Capability metadata and tool responses are frozen benchmark fixtures. Keep all production ownership, artifact provenance, confirmation and validation rules.
