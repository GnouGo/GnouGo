# Canonical runtime occurrence identity

Source interpretation now supplies action or governing evidence. It cannot select an
operation subject or establish a distinct canonical occurrence. ConstraintsOnly policy
scope remains engine-owned; exact declaration coverage still excludes preservation and
contract-only evidence before admission.

Inside `intent_operations`, unopposed proven actions establish canonical roots in stable
source order. Possible duplicates receive one identity-only decision over compatible
canonical roots: distinct, same_as, not_an_operation or unresolved. Action spans, kinds,
requiredness, execution/resource boundaries and baseline authority stay fixed. Governing
evidence attaches after the complete root set, automatically for one compatible target
or through a bounded canonical target set when scope is ambiguous/shared. Shared targets
must each be applicable; alternative guesses are not combined automatically.

Canonical IDs keep their existing owned action anchors or exact baseline coordinates.
Identity pages persist independently of committed operations. Restart reconstructs roots,
reuses completed pages, and attaches governing evidence without changing root IDs or
replenishing budgets. Runtime proof 3 and admission proof 4 retain Schema-5 storage,
source proof 4 and declaration proof 5. Historical proofs require explicit reassessment.
No declaration, confirmation, reasoning, token, partition or escalation logic changed.
