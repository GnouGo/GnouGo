## Root cause

`PlanningOperations.DeriveDeclarationExclusions` processes only preliminary `local_behavior` records. The preservation evidence carried preliminary `runtime_action / external_read`, so its fully declaration-covered source span bypassed that exclusion and entered canonical contribution qualification. The domain then offered executable support against the independently established read occurrence. The model selected that invalid semantic interpretation, and current proof validation admitted it.

The engine already knew the exact declaration target, owned coordinates and complete preservation span before dispatch. Preliminary execution kind must not grant authority over that canonical contract. This recurring declaration/qualification authority class requires architecture review; this task adds no producer filter, prompt change or semantic repair.

The later harness governing-role assertion also needs review against complete-clause execution support. The full classification clause retains its rules and fallback as support context, so the harness stop alone would not prove those semantics were lost. The preservation-support defect independently prevents acceptance; the stopped result must not be relabelled as a harness-only pass.
