# Planning clarification

Format-11 planning retains the complete original request and answer revisions. Intent indexing records exact source clauses and explicit dispositions for candidate interface declarations. Public caller inputs and returns differ from files, local exports and internal effects. Original neighboring naming and type clauses are consulted before asking for missing facts; missing types or defaults are never invented.

Use the existing clarification action for a material unresolved business fact or choice. A question presents bounded alternatives and a recommendation where useful. Automatic mode does not silently answer a material ambiguity or widen permissions. Runtime `human.input` and execution confirmations remain separate.

A pending clarification is bound to its exact host context, baseline, requirements and scope. Answers retain original requirements and accepted work, append authoritative answer history and resume the existing phase. They cannot authorize unrelated edits, reset allowances or reconstruct a pending request from newer context. An answer alone does not prove business fulfillment.

Recover current issued requests and receipts exactly. Older planning formats are rejected without changing their encrypted records or financial reservations; starting a fresh session is required. No historical clarification or repair-schema execution fallback remains.
