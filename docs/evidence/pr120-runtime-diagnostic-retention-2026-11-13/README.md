# Bounded retention for a finished tool-free diagnostic

## Demonstrated local lifecycle gap

The isolated batch diagnostic was issued through the benchmark runtime adapter instead of the protected Server probe path. Its immutable `isolated_source_consumer` record therefore does not meet the existing Server `provider-probe` retention contract. The missing receipt leaves a logical unresolved request, so the ordinary guard would prevent a later full Code execution even though the complete HTTP reservation is already retained. Relabeling that old report, releasing the hold or bypassing the execution guard would be incorrect. The probe still establishes its stated incomplete transport evidence, not protected Server planning qualification.

## Scoped correction

A separate internal `tool-free-runtime-diagnostic` retention kind reuses the existing preview/apply operation and version-1 closure shape. It accepts only the recorded finished failed source-consumer form with explicit no-navigation/no-business/no-fragment/no-original-session-change evidence, valid source/harness/template hashes and the exact request. It requires one captured foreground runtime attempt, no received body/result/protocol completion/usage/receipt, a matching registered configuration and reservation, and a strict JSON-schema wire request matching the model, prompt, schema and actual output bound. SDK proxy modes, native/legacy tools, conflicting token bounds, execution/planning markers, stale ownership/policy/configuration and invalid time windows are rejected. The established Server probe contract remains strict and unchanged.

Only a new administrative closure is written. Every old run/request/failure/HTTP record and its exact fee remains immutable. The root run and its execution/Copilot aliases become permanently non-replayable. No success, recovery, release, budget grant, provider/model/transport change or permission follows. Application/TaskPlan schemas and MCP/public contracts remain unchanged; no new journal table or planning protocol version is introduced.

[Controlled tests](controlled-tests.json): 660 financial cases pass Release `-warnaserror`, including 26 diagnostic authority cases, stale-preview rejection, repeat-apply protection, cold scope guards and exact original/accounting preservation. The compiled unsupported-kind failure is the semantic red; fixture-only errors are not counted as that reproduction. [Actual read-only preview](preview.json) binds the finished request and its full EUR58.860157025539211262521433082 reservation. It is **not yet an applied closure** in this commit.
