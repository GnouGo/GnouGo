# Generic, contract-grounded TaskPlan requests

Baseline: `12608c90599a82417c37d05e8c61d28744ef50ad`. This correction changes fresh request presentation, not compiler v15, execution, permissions, correction authority or public TaskPlan types. No provider call, live workflow, financial change or historical-session advancement was made. PR #117 remains draft.

## What changed

Shared generation, revision and repair guidance now describes operations, supplied evidence, typed bindings, decisions, contracts, conditions, iteration, exports, exact identities and cleanup. It no longer prescribes pages → candidates → visits → rows, conventional producer flags, description relevance, headers or writer paths. Description criteria are explicit inputs to the description fixture. Dynamic requests, capability descriptions, contracts and recorded answers—including documents containing business names or YAML—remain intact.

The planning skill contains the user's permanent genericity rule verbatim. The host's authored-workflow revision context now describes intent and approval without a serialization-format instruction. No production vocabulary blacklist, scenario trigger or additional model call was added.

Fresh full-proposal schemas restrict accepted root-export names, independently of nested scope exports. When discovery is closed, complete inspected operation/result-port domains may be paired in the schema; accepted public-output names are constrained only when already known. Open discovery and newly proposed local producers remain subject to existing semantic validation. Operation-input schemas and literal domains are retained.

These extra domains must fit supported schema limits and the complete request's existing safety margin. If enumeration is too large, the original shape remains and semantic compilation/coverage still enforces the exact obligation. Required contracts are never displaced to make room. Historical issued requests, repair templates and authority fingerprints remain unchanged.

The complete Planning suite passes **1,575/1,575** with `-warnaserror`. It includes generic request isolation, clarification/repair/revision requests, accepted output domains, paired operation/port domains, punctuation/Unicode, bounded fallback, legacy schemas and committed-response recovery. Earlier test failures are retained: schema nesting/size overages, scripted fixture transport errors, outdated expected diagnostics, and a comparison that mixed different optional-contract packing. Each was corrected without raising limits or loosening semantic validation.

Previously invalid names/ports can now fail earlier as `PLANNING_RESPONSE_INVALID`; unchanged semantic checks continue to report commitment and scope errors when the issued schema cannot enumerate them. No invalid candidate becomes approved. The unchanged [composition](corrected-proposal.json) produces byte-identical [v15 YAML](corrected-workflow.yaml), with [hashes](composition-compatibility.json).

The independent workbook checks validate complete observations, actual visits, exact action arguments/text, headers, blanks, order, output paths and cleanup. [XLSX files and separately decoded cells](local/workbook-cells.json) are retained: ten-item cases have 11 rows; the complete-empty case has the single supplied header. Repeated selections and unfamiliar destinations are preserved. Incomplete acquisition, unoffered IDs and denied actions stop affected work. Review fixtures perform local clone/check work; deterministic remote adapters verify exact feedback, truthful failed-check outcomes and no publication after uncertain completion. Restart adds no committed effect or inference. These are local execution proofs, not remote capability or model-compliance proofs.

A nullable test assertion warning found during host validation was fixed using the existing nonnullable question accessor. The subsequent owning build and **18/18** checks pass with `-warnaserror`; [validation logs and counters](validation/counters.json) retain the failed build as well. Skill validation passes using the existing validation environment.

Full serial solution, isolated packaging/AOT/published encrypted recovery and candidate CI are running. Their final outcomes are maintained in the [PR validation report](https://github.com/GnouGo/GnouGo/pull/117#issuecomment-6236662068); this evidence commit records only the completed gates above.

## Limits

Scripted responses prove generic presentation, contract rejection, deterministic compilation and execution compatibility. They do not prove better first-response behavior from a real model, semantic correctness of arbitrary generated plans, or live business acceptance. Exact operation presence and compatible types still do not establish a business association. Further model evaluation requires separate authorization.
