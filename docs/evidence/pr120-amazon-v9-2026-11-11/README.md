## Evidence and implementation

The source-only diagnostic showed that three literal `/clk?…` links independently
reach product `B0H8RD31XM`, not stores. They have one original empty-ASIN container
and one heading-bearing link. Neither the empty identifier nor equal destinations
alone establishes an occurrence. The newly authorized rule requires every link's
own complete ordered redirect/document proof, consistent original context, exactly
one heading and no conflicting or unresolved context link or semantic occurrence.

Identity lives in a separate evidence map; no source record or `data-asin` value is
rewritten. The existing context grouping, source-order and duplicate-occurrence
checks consume that independent identity. Distinct contexts stay distinct even
when they resolve to the same product. Existing store navigation still requires
no product heading/occurrence. Missing or contradictory evidence remains failure.

The isolated host adds only literal `/clk?…` on the already approved sponsored host.
The guard grants the next exact source-resolution link, then original primary
product links after all source contexts qualify. Close, failed/contradictory reads
and new searches revoke authority. Direct store entry, decoded targets, invented
URLs, additional hosts, normalization and old-grant inheritance remain forbidden.

V9 retains every raw event and publishes each source-resolution reference, event
index, product/store kind and `business_visit=false`. Those early reads do not
supply business-visit counts or workbook field evidence. Every later required
first-N business visit must still occur in source order and support the actual
Excel cells. Execution success, writer receipt and cleanup remain mandatory.
No rule was added to the production engine, TaskPlan or public contracts.
