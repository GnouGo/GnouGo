diagnostics and scoped repair only. TaskPlan, compilation, runtime, `mapping.dynamic`,

## Behavior

- Generation distinguishes local dependencies, ancestor captures, explicit scope
  exports and task presence. Data bindings already establish dependencies.
- Diagnostics identify consumer/producer scopes, execution phases and available
  exports. Repair context retains ownership without making context tasks editable.
- Fresh dependency repair schemas exclude inaccessible, self, cyclic and invalid
  phase targets. Applying a patch preserves unaffected edges and rejects duplicates.
  Nested captures and scope-output references participate in cycle exclusion.
- Existing exports are reused; missing chains require diagnosed additions and
  explicit conditional counterparts. No branch fallback is invented.
- An immutable inaccessible guard stops with `REVISION_REQUIRED`, even alongside
  editable findings. Separately authorized producer/export repairs remain possible.
- Original version-7 authority verification is retained for already-issued requests.
  A fixture generated by frozen candidate `34bfd604` verifies unchanged schema,
  fingerprint, baseline and tenant checks after restart. New requests use the
  narrowed permissions; all patches still undergo full validation.

For example, a nested selector exports `record`; its enclosing preservation scope
exports that same value. An outer consumer reads `preserve.record`. It cannot test
`present(selector)` outside the selector's scope. Such a guard needs explicit
revision, not automatic substitution with `present(preserve)`.
