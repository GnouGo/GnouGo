Production uses schema 5. Old storage is not upgraded or read by a compatibility path.
For read-only historical replay, run `scripts/planner-schema4-audit.sh SESSION REVISION`.
Use `scripts/planner-schema4-audit.sh --all-retained` to inspect all pinned retained revisions.
`--verify-fixtures` checks current synthetic execution fixtures against the encrypted
historical catalog in memory, through the same read-only audit boundary.
It builds the pinned historical benchmark in a temporary checkout and permits only its
receipt-only `replay` command. It cannot start, resume, capture or approve a live session.
The current benchmark operates only on schema-5 snapshots and namespaces.

Behavior repairs select issued values or deterministic node/port templates. Known
review text is resolved exactly, and forced reference corrections use no model call.
Cross-workflow producer results receive coordinator-owned ports and declared schema
references. An opaque result or unproven conditional projection stops at its boundary.
Repair scope and binding catalogs are persisted before dispatch. A staged field and
its committed graph coordinate share one semantic correction allowance across gates.
Human revisions retire superseded obligations through issued evidence references.
Removing an operation removes only its exact derived ownership entries; unrelated
content and host policy remain intact. The changed behavior requires renewed review.

The offline corpus tests reference ownership/staleness, constrained response domains,
coverage and sizing, deterministic assembly/propagation, field repair scope and
monotonicity, provider capability checks, persistence and exact artifact approval.
Successful synthetic execution is not evidence of live model convergence.

Live validation requires separate authorization. First prove one complete CodeReview
session, then three independent successes on the same frozen commit, catalog, policy
and budgets. Success requires FinalReview, all 18 independent execution fixtures,
and exact artifact-hash approval. The isolated benchmark policy remains
`git_compare_refs -> copilot_review`; production contains no such restriction.
Keep every failed or unverifiable attempt. Unsupportedness or a fixture self-check
cannot count as a successful generated workflow.

The [offline validation record](planner-schema5-validation.md) distinguishes component
checks, historical inspection and fixture self-checks from the live acceptance still
required before claiming CodeReview convergence.
