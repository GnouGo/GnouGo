# Attachment-only declaration constraints

The correction starts from `369ac23`. It adds `declaration_constraint` to source
interpretation and the existing `intent_declarations` attachment domain. Public
roots, behavior assembly, model profiles, paging, output escalation, the compiler
and runtime interfaces are unchanged.

A constraint selects only `modifier_of` an issued canonical target or `unresolved`.
It cannot create a declaration, alias it, assign a default or change direction,
scope or presence. Root presence choices exclude constraint-only evidence. Existing
materialization retains the selected evidence as modifier references and complete
clauses; existing behavior assembly renders them in the canonical port description.
Unresolved, unlocated or stale attachment proof stops before review. Real supplied
`explicit_value` obligations remain outside this path, and host constraints grant
neither operation nor public-port authority.

Source and declaration proofs are version 4. Schema-5 databases and encrypted
namespaces remain unchanged. Historical classifications and receipts are audit
evidence; no production conversion or migration is provided.
