## Root cause

Preliminary runtime classification and coverage both controlled executable qualification. Candidate effect ownership, requiredness and an `action` label could substitute for a positive proof that the owned evidence requested execution. Complete coverage protected against missing realizations but did not establish the authority of their supporting spans.

## Authority analysis

The pre-patch review answered the protocol's ten questions:

1. The failed invariant was property evidence satisfying executable support.
2. Canonical contribution qualification owns that invariant.
3. The engine already knows source ownership, declarations, baseline coordinates and finite effect domains. It does not deterministically know whether arbitrary prose requests execution.
4. The invalid choice existed because raw `action` unlocked coverage support.
5. Validated qualification now fixes support versus governing authority before coverage.
6. Production uses references and stable contracts, without fixture wording or keyword vetoes.
7. Mixed clauses, optional omission, baseline annotations and independent occurrences require protection.
8. Separate owned boundaries remain distinct even with shared public endpoints; existing independence tests and new contribution tests cover this.
9. Semantic qualification moves to one canonical owner; preliminary role selection and independent coverage role selection disappear.
10. Another verified blocker in this authority class requires architecture review before a targeted fix.

Qualification remains a bounded semantic assessment. A proof record does not make an incorrect semantic answer infallible; it makes authority explicit and prevents subsequent stages from independently strengthening it.

## Implemented action

The existing `intent_operations` sequence is now:

1. Validate source/runtime evidence and canonical declaration exclusions.
2. Ground candidate occurrence ownership and workflow scope.
3. Qualify complete owned contributions against issued effects.
4. Resolve complete realization coverage and scoped public dataflow using the fixed qualifications.
5. Apply revision decisions, resolve admission-owned data dependencies, validate and commit atomically.

Runtime response schemas no longer contain the preliminary `evidence: action|governing` choice. Historical `EvidenceRole` remains deserializable but grants no current authority. Baseline execution qualification uses current typed structural ownership; owner-bound annotations govern only.

`PlanningExecutionContributionProof` records the runtime parent, decision/domain fingerprints, exact contribution references, effect bindings, qualified roles, positive bases, origins and a canonical fingerprint. Requested support must bind owned execution evidence to either a result owner or an existing occurrence proof. Exact baseline execution qualifies deterministically. Engine-known source/declaration exclusions are also recorded. An explicit semantic exclusion must cover owned evidence and cannot contradict overlapping support.

Mixed-purpose evidence can select issued subspans. Every non-whitespace character of the parent evidence must be covered; text is never automatically trimmed. Separate support and property records can share a runtime parent while retaining distinct contribution IDs. Canonical operation IDs are unchanged.

Coverage maps use those contribution IDs. Governing qualifications cannot appear in `SupportingEvidence`; support qualifications cannot be reclassified by coverage. Governing targets must be selected realizations. Optional omission and necessity conflicts retain their existing coverage rules. Jointly established applicability is reused without another governing request.

Proofs remain on existing admission records and durable decision pages. No snapshot collection, operation graph, phase, service, runtime interface or public command was added. Dependencies, confirmation, reasoning, budgets, token ceilings, partitioning and singleton escalation are unchanged.
