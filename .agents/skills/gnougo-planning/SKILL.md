# Planning

Requirements → Discovery → LLM TaskPlan → deterministic compiler → PlanningGraph → YAML → validation → approval.

## Contracts and compilation

- TaskPlan is explicit semantic intent; PlanningGraph is the sole executable representation. Add no intermediate representation, model phase or parallel planner.
- No MCP server/tool-specific logic in Flow.Planning or Flow.Core: never branch on names, catalog IDs, URLs, domain terms or prompt keywords. Producer behavior and provider mappings belong in producer metadata or injected integrations.
- Generic metadata ranking is permitted only for discovery presentation: rank retained candidates across pages using request/requirements plus source-scoped refinements, pack optional contracts within 90% of the saved input allowance, retain query/cursor expansion and complete receipts; explicit discovery inspection selections keep exact contracts visible until replaced and grant no execution permission; never infer behavior, types or permissions from relevance.
- Catalog-owned fixed/request bindings stay host-owned: omit them from editable ports, reject explicit overrides, and permit only diagnosed removal in repair. Preserve full contracts and validate the effective request.
- Bind through authoritative JSON Schema and validated provider-neutral metadata. Expose declared finite domains in compact indexes; constrain admitted operation literals and nested array/object values with the supported response-schema profile; factor nested schemas without dropping constraints, and keep unsupported wire constraints and reference checks in full semantic validation. Prefer generic contract fixes over prompt exceptions or inferred behavior.
- Project a clone of each completed new response schema before token packing, hashing and persistence. Omit only valid runtime patterns outside the JavaScript-Unicode/nonbacktracking intersection; retain original contracts in prompts, semantic checks and repair fingerprints. Strictly preflight nested schema positions and references before reserving calls. Preserve issued requests during recovery; never retry a rejected schema unchanged or fall back to unrestricted JSON.
- The model selects operations, business bindings, bounded structured scopes and choices with literal alternatives. It must not generate executor envelopes, wire paths, JavaScript, projection recipes or invented contracts.
- Request the smallest sufficient plan with explicit objectives. Compact only representation defaults; never drop business intent or weaken contracts. Accepted requirements remain host-owned. `value` assembles, `field` selects declared fields, `json` serializes; `transform` extracts or interprets data with an explicit closed result type, never simple wiring. Runtime transforms receive only their objective and inputs; operation objectives do not supply arguments. Bind every required fact and fixed instruction explicitly.
- Clarify material uncertainty about caller inputs, missing facts or business alternatives within the existing response loop; clear requests keep direct generation. Questions pause even in auto mode, offer a recommendation and custom text, and never approve execution. Persist complete question/answer batches before continuation; retain cumulative budgets and origin/tenant ownership. Caller inputs belong to accepted requirements, not tool argument lists. Fresh intent also declares business output names/types in requirements.outputs; freeze that interface and require explicit revision for changes, without restoring outcome proof mappings. Unknown producer contracts cannot justify invented inputs or fields.
- Permit bounded discovery before requirements are established; require accepted business intent and caller inputs before a plan. Fresh sessions use `IntentVersion=2` and business requirements plus TaskPlan only: no model-authored effect/placement/coverage annotations or outcome-to-task proof mappings. Derive technical review from actual tasks, graph and contracts. Missing effect metadata remains usable under conservative confirmation; it is not permission or proof of execution. Static validation cannot prove that arbitrary prose was fully implemented; review accepted requirements against the plan and verify execution independently.
- New repairs use private envelope 7 and only diagnosed TaskPlan slots. Keep inspected-contract admission, typed bindings, fixed-input ownership and compatible repair sources independent of retired annotations. Unfinished legacy sessions require explicit revision; validate an available completion against its original schema and restore durable accounting without applying its obsolete proposal. Unknown completion requires reconciliation. Preserve requests, receipts, budgets, historical hashes and approved artifacts; regenerate and approve legacy unapproved artifacts. No format-10 migration or automatic saved-workflow rerun.
- Close required input/output contracts after graph construction and before final mapping lowering: check types, availability and declared artifact provenance with existing validators. Keep predicates, JSON encoding and cleanup guards typed until YAML generation; no early JavaScript or extra planning phase. Report unsatisfied business bindings as `CONTRACT_UNSATISFIED`, retaining the precise source, consumer and repair location. Compiler plumbing defects remain compiler failures.
- Defaults come only from authoritative schemas or accepted public-input contracts. Validate before use, fill absent required slots only, and preserve explicit nulls and omitted optional arguments. Never repair a missing observation with a guessed fallback.
- No mapping executor in TaskPlan: typed → JavaScript compiled at final lowering; insufficiently typed → DynamicMappingExecutor at runtime. Keep adaptations in existing graph bindings; validate closure before lowering. Opaque bindings require authoritative consumer targets or explicit extract result declarations, approved bounded inference and available sources. Never bypass known incompatible contracts or manufacture provenance. Unconstrained typed values may use deterministic consumer-constraint guards; reject invalid literals, incompatible finite domains and contradictory declared constraints. Select discriminator-dependent contracts from unambiguous literal selectors before binding their ports. Do not demand invented enums for runtime strings merely to satisfy a pattern.
- Business transforms support optional `mode: extract | interpret`; omission preserves interpretation. Extraction selects observed JSON/text/HTML values through a restricted source-grounded sandbox, at most one generation and one repair per invocation. Do not add invented classifications, status labels, counters or null placeholders to extraction results; use explicit interpretation or declared deterministic business operations when those results are requested. Nullable is not a default. Defaults require verified absence and authoritative target defaults; explicit nulls and invalid observations remain failures. Cache only validated scripts per tenant, using structural JSON signatures and conservative text hashes; persist receipts and retain unknown-completion reconciliation. Interpretation/synthesis stays explicit. Independent execution oracles establish semantic correctness.
- Prefer producer-owned compact typed observations and selected fields over raw page/tool dumps. Retain observed text, grouping and source URLs; truncation or continuation requires targeted reads or bounded continuation, never guessed completeness or an empty fallback. A capture limit still requires narrowing when no cursor remains. Preserve requested per-item action sequences and extract from each actual result. Authorized visible blockers use explicit conditional operations on observed controls followed by a fresh read. Split adaptive work into bounded, independently verifiable tasks with shared cumulative budgets; use declared runner capabilities or compatible approved operations, never expand authority.
- Publish/consume versioned producer effect metadata through MCP transport; metadata grants no permissions. Prompt and schema must use the same admitted exact contracts; index-only operations need inspection. If a runner lacks requested capabilities/evidence, retain the requested action and clarify discovered compatible alternatives, or report the precise limitation. Fixed creation inputs may be read-only repair context, never added edit authority.
- Reuse equivalent existing export chains deterministically. Require explicit collection selection, missing exports, defaults and branch values; never invent them or cross ambiguous group boundaries. Cleanup remains explicit unless an authoritative operation owns its lifecycle; a lifecycle effect alone never authorizes deletion. Reuse declared resource locations for creation and cleanup, including partial failure. Optional producer artifact locations identify address spaces, materialization, uses and releases; validate literal selectors against exact schema branches. Reject known returned-artifact deletion and use-after-release before approval. Unknown/dynamic lifecycle remains an explicit review limitation, not inferred ownership; a requested report must be written outside released temporary resources before cleanup.
- A structural scope without exports supplies no business data: reject consumption of its whole result with `TASK_EXPORT_REQUIRED`, rather than passing an empty object to a downstream transform. Use `dependsOn` or `present` for ordering/presence; keep effect-only scopes valid and never infer an export from their last task.
- Compile checked selections, whole values and per-item collections to final JavaScript in checked `set` expressions; use `switch` for routing. Do not reintroduce retired .NET `value.project`, `value.validate`, `array.project`, `assert.non_null` or `decision.evaluate` steps. Preserve first-present-path semantics, explicit nulls, bounds and provenance; the model never authors projection settings. Whole-value guards for typed computations use an ordinary set envelope and its output schema; never pass computed expressions as structural sandbox sources.
- Derive loop element contracts from every collection alternative across scope exports. A literal empty array contributes no possible element; unknown contents remain opaque. Preserve the complete collection contract in runtime guards and reject non-array alternatives or incompatible consumers.
- Preserve optionality, nullability, enums, opaque contracts and availability checks. Fail closed on ambiguity or unavailable contracts. Envelope presence proves neither payload non-nullability nor external success.
- Derive effective operation outputs consistently during semantic validation, lowering and graph validation. Preserve approved agent payload schemas and nested unknown contents through the existing opaque representation; passing data across a scope never grants typed access to undeclared fields. Preserve the original discovery contracts and issued requests.
- Artifact origin comes only from declared producer metadata; preserve it through checked identity-preserving bindings. Types, literals and transforms cannot manufacture provenance. Present artifact kinds and business ports in compact discovery, never wire pointers; find missing prerequisites with bounded exact-kind metadata queries.

## Repair and approval

- Approval requires explicit human acknowledgment of every accepted requirement through `ReviewedRequirementIds`, bound to the exact revision and artifact hash. Compare actual operations, loop bodies and data dependencies; missing or uncertain coverage requires revision. Never populate acknowledgments automatically or treat compilation as proof of prose completeness. Revisions clear review; historical approvals remain unchanged.

- Derive minimal complete edit permissions from the immutable baseline and diagnostics. A diagnosed optional operation binding may be explicitly omitted only under its authoritative contract; null is not omission. Expose only incompatible producer constraint leaves. An input nullability diagnostic may authorize that exact leaf when its consumer rejects null; preserve requiredness, defaults and other input fields, and require consistency with accepted requirements. Dependent revalidation does not grant edits; unknown locations never widen scope.
- Return TaskPlan for generation and typed host-issued patches for repair edits. Reuse revision permissions, apply to a clone and fully revalidate. Structural slots may insert only a contract-proven prerequisite chain before its diagnosed consumer, replace an invalid leaf task while preserving identity/objective/dependencies, or remove a diagnosed pure forwarder through equivalent host-owned reference rewrites. Preserve unrelated structure and ordering; never regenerate the baseline. Bind recovery to the original baseline, complete permissions, contracts and issued schema; never silently rebase or expand older pending permissions.
- Preserve unrelated tasks, interfaces, ordering and choices. Reject unauthorized proposals atomically; retain discovery receipts, request identities and cumulative budgets through recovery. Validate recovered responses against their saved request schemas.
- A clarification response applies no repair edits. A submitted custom answer is an explicit intent revision with a retained baseline and invalidated artifacts/approvals, never a raw typed binding or extra repair permission. Retain original schemas and authority as historical records; never redispatch or reinterpret retired repair envelopes. Current envelope 7 includes clarification authority and accepted requirements. Optional interaction fields do not migrate historical approvals or planning format 10.
- Designer hosts must hold a shared cross-process session lease before advancing or applying commands/approvals. Contention defers work. Durable cancellation closes dispatch without discarding a late receipt. Resume from a saved response requires explicit action, original request/schema/index identity and durable accounting; unknown completion remains stopped, with conservative usage retained on an explicit retry.
- Reserve one proposal and one repair when allowed; additional repairs are opportunistic within saved ceilings. Successful discovery clears only resolved response errors, never history or counters. Enforce issued schemas and stop safely; token settings cannot replenish calls.
- A missing artifact producer permits structural repair only with exact policy-allowed producer contracts. Every inserted task must lie on the diagnosed required-artifact dependency chain; unused additions fail atomically. Stop for explicit semantic revision when that proof is unavailable. Unavailable contracts are uncertainty, not proof of absence.
- Invalid generated plumbing is a compiler defect, not a model repair. Do not remove guards or relax validation to accept it.
- Keep agent scope literal and approved. Workspace alone may reference available `value` constants proven by the compiler and emitted as literals; inputs, operations, transforms, choices and loop-derived values cannot define it. Choices grant no permissions and never substitute for operation-owned runtime approval. Recompilation must reproduce the reviewed artifact; changed intent, selections, contracts or artifacts invalidate approval.

## Development

- Preserve failures; reproduce with sanitized fixtures and independent oracles. Add a deterministic regression, make the smallest generic correction, and run affected tests and CI checks. Never weaken an oracle.
- No paid/live evaluation without explicit authorization. Authorized generic-fix iterations share a frozen corpus/oracle and cumulative budget; retain all failed and inconclusive identities and never overwrite or pool them into a later revision's success rate. Simulations and assistant claims are not external execution evidence.
