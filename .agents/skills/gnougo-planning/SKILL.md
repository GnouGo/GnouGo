# Planning

Generate the smallest sufficient executable business TaskPlan for the user's request. Preserve necessary validation, shared computation, cleanup and recovery boundaries; task count alone is not a measure of simplicity.

Never introduce use-case-specific instructions, examples, heuristics, capability names, business entities or expected workflows into this skill, shared planning prompts or production planner logic. Scenario context comes from the user's request, discovered capabilities, authoritative contracts and retained session context. Keep scenario-specific examples and independent expected outcomes in tests and evidence. Do not filter legitimate domain text from dynamic context.

## Responsibilities

Prioritize deterministic validation, precise diagnosis and bounded correction over perfecting the initial prompt. New sessions build one semantic TaskPlan incrementally, from available producers toward consumers: retained requirements and material clarification, capability discovery and exact-contract inspection, then bounded Structured Output extensions. A simple workflow can finish in one draft, followed by its local advisory review. Reuse the existing coordinator, contracts, journal and encrypted session store; add no executable IR or parallel engine.

- Fresh compact construction first indexes authoritative request and answer passages, then selects one immediate business substep with its original requirements, available inputs, intended outputs, dependencies and task kinds. Resolve prerequisites and select cleanup, exports and scope closure through the same frontier. Never generate a future workflow outline or replace original intent with a summary. Unprocessed source pages and unresolved requirements block completion.
- Prefer coherent original source boundaries within captured byte limits; retain explicit continuation links when a passage must span pages. Review the complete linked obligation before closing it. Separate verbatim clause classification from targeted extraction of explicitly declared caller/public interfaces; prose-only indexing needs no recursive type/default grammar. Pending interface extraction blocks generation and completion. Capture this presentation protocol only for fresh sessions and recover historical issued schemas unchanged.
- Extract interface-bearing clauses from one bounded source page together so adjacent naming and type constraints remain available before accepting declarations. Keep their business requirement statuses separate and preserve the grouping captured by previously issued classifications.
- Isolate standalone caller/public-interface declarations when their original boundaries permit it. Keep each action with adjacent composition and result constraints in one requirement, even when that obligation declares a public result; interface marking does not require splitting it. Narrower extraction context is a controlled presentation experiment; it does not prove why a prior response exhausted its reasoning allowance.
- Ask for the smallest interface declaration supported by those clauses; do not design downstream payloads or validation. Keep absent restrictions absent and retain every declared constraint. Evaluate presentation changes with fresh identities and unchanged model settings; an empty reasoning-only response does not establish its own cause.
- Keep one earliest unresolved original requirement as the selection anchor. Retrieve exact prerequisite clauses through bounded supplemental pages without surveying future work; a page never replaces the anchor. Present supplemental original evidence once. Bound navigation descriptions and port directories with explicit completeness, versions and retrieval addresses, while retaining full originals. Unspecified interface constraints stay unspecified; zero is a real bound, never an unbounded sentinel.
- Keep presentation local to that substep. Discovery queries and capability selection use its needs; previously inspected contracts remain retained evidence, not mandatory context for every later call. Use separate small response schemas for intent, selection, discovery and evidence; generation exposes only selected semantic task kinds and operations. Preserve the selected kind's necessary semantic guidance, including scope exports and the distinction between total iteration bounds and concurrency. - Distinguish local evidence addresses from provider continuation cursors. Issue bounded provider-action pages with exact source/cursor pairs; the host supplies the retained substep query. Keep applicable global constraints in discovery. After bounded inspection, an unsuitable tentative operation step may be reselected under the existing correction allowance and exact scope/requirement boundary; retain the rejected decision and evidence, and never turn capability absence into invented execution or wider revision authority.
- Select preparatory bindings only when the existing value grammar can express them or an inspected contract requires them. A tentative kind or import mismatch is a bounded local correction, not a missing business fact: retain the diagnosis and reselect within the same scope, requirements and cumulative correction allowance. Preserve issued schemas and accepted checkpoints; never invent operators, interpolation or runtime dependencies.

Compact descriptors support selection; version-addressed schema views carry original-contract hashes and retain required ancestors, siblings, alternatives, references, effects, permissions and provenance. Accepted bindings remain immutable.

Retain per-component byte/token estimates with exact issued request identities; distinguish estimates from whole-call provider usage and keep measurements out of artifact identity.

Apply an extension to a clone identified by the accepted checkpoint and hash, and commit it atomically only after deterministic validation and local review.

Validate every concrete contract, binding, reference, type, provenance, assertion, permission and dependency immediately using the compiler's semantic preflight. Future dependencies remain non-executable obligations; never use placeholders or unresolved references. Open containers expose no completion or outputs until their children and compatible exports are closed.

Retrieve original evidence through bounded identity/version-addressed requests. Historical construction retains its captured optional-contract admission behavior. Do not routinely resend the entire plan, original request, history, requirement directory or catalog, substitute a summary for authoritative intent, or silently truncate indispensable evidence.

- A stateless discovery call may need an earlier original description to compare newly discovered alternatives. Permit that targeted reread only after successful prior retrieval and genuinely new allowed operation identities or versions, under the exact issued request's captured knowledge identity. Reordering, empty pages, cursor changes and diagnostics are not progress. Keep one-read-per-knowledge guards, consumed operation pages, exact versions and cumulative accounting; never clear history or resend cached contract prose automatically.
- While supplying requested discovery evidence, retain only a bounded directory of relevant operation identities whose descriptions were already read for the current baseline. Names and effects aid selection; they neither repeat contract prose nor prove complete inspection or authority. Keep exact retrieval and non-progress guards. Request one exact evidence address per string; never concatenate addresses. Declared caller-input bindings provide runtime values, so discovering their consumers does not require those concrete values during planning.
- Constrain replacement selections to the existing fixed requirement identities and cardinality, preserving host exact-set checks. Select every existing binding used by the fragment, including local scope inputs and closing exports. Diagnose missing imports precisely; changing a selected import requires reselection, not a renamed export or a widened binding guard. Compact intermediate-review bookkeeping separately from task evidence: checkpoint hashes and cursors must not crowd out original clauses, interfaces or the fragment. Explicit required-size conflicts remain findings, and finite supported capacity remains uncertain where the original request does not specify it. Presentation guidance never changes accepted tasks or host execution limits.
- Review each deterministically valid draft with a bounded advisory Judge. Add targeted intermediate reviews at multi-fragment scope closures, joins and captured checkpoint intervals; coalesce overlapping triggers. Verify report schemas, locations and evidence. An invalid or inconclusive report cannot accept a checkpoint. A valid report may retain explicit uncertainty; its opinions are neither deterministic proof nor authorization. Never add a final whole-workflow LLM Judge.
- Present accepted export declarations for the selected scope when extending it, and the applied candidate interface when reviewing its closure. An extension adds exports; an empty addition preserves accepted exports. These paged construction views do not make an open container consumable. Give Judges the selected task kind's essential port semantics: a transform's required object result type declares named fields, and a named output reference consumes that field's type.
- Include the selected scope owner's relevant export semantics during closure review: iteration aggregates each body export into an ordered array on the enclosing task. Keep discovery's substep view limited to decision-relevant fields and compact input bindings; retained draft-only metadata does not belong in every navigation request.
- Give scoped Judges exact retrieval links for referenced accepted producers, their child scopes and reusable groups reached through supplied call evidence. Group identities are not task identities. Distinguish those evidence-request addresses from finding locations and evidence, which must resolve as JSON Pointers into the supplied context. A bare identifier is not an evidence address; invalid reports remain inconclusive and cannot accept a checkpoint.
- Reuse typed scoped repair for the current candidate. If a required producer is absent, use bounded candidate replacement when authorized; an output-only patch cannot supply the missing operation. Preserve already issued requests and explicit edit restrictions. Earlier changes require dependency-based invalidation, including data, control, captures, exports, groups, cleanup, contracts and accepted decisions. Verify preservation of independent fragments and commitments before rebuilding only the affected region. Preserve invalidated originals as evidence. Stop repeated candidates, non-progress, exhausted allowances or unprovable preservation.
- Persist the exact phase, candidate, context manifest and issued request before dispatch. Resume saved receipts once without regenerating accepted fragments or replaying uncertain calls. Judges, evidence requests and corrections share existing cumulative allowances and journals; admit a draft or correction only when its required review also fits. Capture configurable limits and any explicitly selected large-workflow preset before dispatch; never increase them silently.
- Finalize only with closed scopes and dependencies, explicit requirement statuses and complete deterministic validation of contracts, interfaces, references, effects, provenance, permissions and cleanup. Keep unsupported business claims unverified. Preserve deterministic JavaScript generation through PlanningGraph and compiler v15 YAML lowering, followed by existing artifact approval and execution checks.
- Historical generation and global-review behavior exists only behind captured compatibility versions for safe continuation of issued sessions. New sessions cannot select the monolithic path or disable scoped reviews using a legacy option.

- The LLM selects business operations, arguments, decisions, conditions, dependencies and requested results. It identifies semantic sources and fields using existing TaskPlan bindings. It does not author executor envelopes, wire paths, scripts or technical proof mappings.
- The deterministic compiler resolves declared bindings, performs typed copying, field projection and object/row assembly, derives technical dependencies, validates contracts and lowers through PlanningGraph to YAML. YAML is never the model's target representation.
- Compilation must not invent business decisions, defaults, missing values or external effects. Compatible shapes and similar names do not establish meaning, identity or producer ownership.
- MCP producers own operation contracts, effects, permissions and provenance. Discover unavailable contracts; do not simulate external work with transforms or replace execution with an unrequested document.

## Composition and contracts

Prefer direct consumer bindings and scope exports for deterministic values. Keep an explicit task only when it performs business work or preserves a necessary computation, validation or durability boundary. Do not replace interpretation with copying merely because their types match.

- `requires` is a mandatory Boolean assertion: false fails before work. `conditional` routes alternative execution paths. Preserve short-circuit order and nullable access checks.
- `extract` returns observed facts from supplied evidence; `interpret` performs genuine decisions or requested synthesis. Neither performs tool calls. Historical omitted transform mode retains its meaning.
- `value` is deterministic typed assembly. `field` selects one literal declared object property. `lookup` reconnects records by identity; it does not merge objects. `flatten` concatenates one explicit collection level. `foreach` expresses repeated work, including a necessary typed collection projection.
- Preserve exact requested content, opaque identities, order, repetitions and explicit nulls. Missing differs from null; defaults require authoritative declarations. Never fabricate data to satisfy a result contract.
- Preserve complete required observations and producer provenance. Narrow decision inputs through explicit declared fields; do not silently sample, truncate, filter or deduplicate. Bounds do not increase host limits or prove completeness.
- Validate types, constraints, nullability, scope, availability and provenance before lowering. Keep opaque contracts opaque. Preserve complete schema alternatives and runtime validation; compiler defects are not model repair requests.
- Data references imply dependencies. Ancestor captures and explicit scope exports preserve availability; conditional branches expose matching interfaces. Keep normal results in the normal path and genuine preservation/cleanup in finalizers.

## Intent, correction and approval

Compare accepted requirements and actual work with the original request and retained answers. Commitments are non-executable obligations grounded in inspected operations and declared producer/public-output ports. Never derive missing obligations from the plan being assessed.

Keep verified clauses, violations and unverified aspects distinct. Operation presence, structured output and compilation do not prove arguments, prose completeness, per-item execution or successful effects. Human acknowledgment does not upgrade uncertainty into verification.

Clarify only material missing business decisions or facts through the existing interaction loop. Preserve recommended alternatives, custom answers and Auto/Human behavior; recommendations are not authorization. Answers preserve accepted intent, correction authority and cumulative accounting. Requirement/interface changes require explicit revision.

Use the smallest diagnostic-derived correction scope under captured policy. Apply edits atomically and revalidate the accumulated plan. Fresh construction may regenerate only the current candidate or its proven invalidation region; historical structural regeneration retains its issued authority. Preserve unrelated work, effects, arguments, ordered assertions, cleanup, accepted interfaces and host-owned bindings. Read-only context grants no edit authority. Stop repeated failures, exhausted allowances and changes whose preservation cannot be established. Explicitly authorized defaults apply only to new sessions; never automatically increase budgets, retries or timeouts to compensate for poor generation.

Scoped business Judges independently compare the retained intent and relevant original evidence with the current fragment after deterministic validation. Their structured observations are advisory, never deterministic proof or correction authority. Use the existing scoped correction and clarification paths; do not infer permissions from judge-proposed edits. Historical optional whole-plan review retains its captured behavior only for compatible historical sessions. Judge calls share the session's existing model-call, token, financial and time allowances, journals and recovery; no parallel allocation or hidden retries.

Before model dispatch, establish compatibility with declared provider/model capabilities and admit the complete serialized request against its effective allowance. Keep input estimates, byte bounds, output reservations and cumulative budgets distinct. Unknown runtime input size is unverified, not proof that a consumer fits. Never truncate indispensable evidence or silently change model settings to obtain admission.

Approval requires explicit requirement acknowledgments, current revision and artifact hash. Recompute contractual coverage; confirmed violations block approval. Do not preselect or manufacture acknowledgments. An explicitly authorized isolated test reviewer must use trusted host-owned authority and artifact-bound evidence, record truthful delegated provenance, and remain unavailable to production approval paths. Individual delegated runtime confirmations must match the exact approved invocation and scope; never grant blanket permission or use Judge opinions as authority. Preserve tenant isolation, encryption, confinement, permissions and cross-process leases. Unknown completion blocks replay and dependent cleanup. Post-execution correction creates a separate unapproved draft.

## Compatibility and validation

Preserve historical TaskPlans, issued schemas, correction authority, receipts, approvals, compiler profiles and YAML. Capture new behavior only for fresh sessions or explicitly authorized revisions; do not reinterpret pending requests or silently migrate historical artifacts.

Reproduce failures with focused regressions and independent business oracles. Check actual emitted requests, exact outputs, effects, cleanup and recovery. Distinguish deterministic fixtures and replay from live-model and execution results. Preserve failed evidence. Paid or externally effectful live evaluations require separate authorization, frozen cohorts and cumulative accounting.

Prioritize complete live business outcomes over additional planning abstractions. Treat smaller schemas as a measured experiment, not proof that reasoning-only failures are solved. Keep model settings and allowances captured; retain unsuccessful responses and stop unchanged repeated attempts. Independent acceptance must check requested structure and available runtime dependencies as well as output values and effects.
Bind independent execution checks to the actual caller inputs, ordered source observations and retained invocation results. A correctly shaped report or output file is insufficient when its identities, order, provenance or claimed command results are unsupported by those observations.

An explicitly authorized benchmark operator may permanently retain a stopped, unexecuted, tool-free uncertain planning request through an evidence-bound append-only closure. Keep its full unknown-usage reservation and every original record; forbid both request replay and continuation of its run. This is terminal inconclusive retention, never reconciliation, completion or permission to execute effects. Other identities still pass ordinary admission. Capture effective transport policy before new dispatches; never rewrite historical policy to make closure eligible.

Bind any separately authorized HTTP-failure retention mode into its exact evidence identity. Require matching retained failure and journal records plus the original captured single-attempt policy; keep historical timeout eligibility and closure hashes unchanged. Restored provider availability does not establish usage or termination of an earlier request. Resume only through fresh independent run identities after the authorized append-only closure, preserving every financial reservation and ordinary admission check.
An HTTP server failure without verified usage does not prove that provider work was absent. Retain its conservative reservation consistently in campaign, run and phase accounting. Preserve the original failure and captured transport policy; do not reinterpret it as a receipt, retry it, or broaden an operator closure to make a blocked campaign continue.
